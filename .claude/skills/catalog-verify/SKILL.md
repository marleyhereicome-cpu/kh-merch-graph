# catalog-verify

`catalog-entry` スキルで下書きした（＝`verified=false` の）`data/catalog.csv` の行を、
元の `source_url` とは別の第2ソース（公式サイトの別ページ、正規小売店の商品ページ等）と突き合わせて、
定価・発売日・商品名などの不一致を洗い出すスキル。人間が最終的に `verified=true` にするかどうかを
判断するための材料を作るのが目的で、このスキル自身が `verified` を書き換えることはしない。

## 手順

1. **対象行を特定する**
   - 指定された `sku_id`、または `verified=false` の行すべて（`data/catalog.csv` を読む）を対象にする。

2. **第2ソースを探す**
   - 1次ソース（`source_url`）とは別の情報源を探す：
     - メーカー公式の別ページ（プレスリリース、公式X/Twitterの告知など）
     - 正規代理店・正規小売（AmiAmi、e-STORE以外の正規取扱店等、`data/channels.csv` の `channel_type=new` を参考に）
     - 一番くじの場合はBANDAI SPIRITSの公式くじ情報サイトなど
   - 見つからない場合は「第2ソースが見つからない」と正直に報告し、無理に作らない。

3. **突き合わせる項目**
   - `name_ja` / `name_en`（表記ゆれの範囲か、実質的に違う商品かを判断）
   - `msrp_jpy` / `price_basis`（税込・税抜の違いにも注意）
   - `release_date` / `rerelease_dates`
   - `character` / `character_en`
   - `jan`（あれば）
   - `official`（本当に公式ライセンス品か、非公式のリーク情報ではないか）

4. **不一致を列挙する**
   - 一致：特に書かなくてよい（全項目一致なら「主要項目は第2ソースと一致」とだけ書く）。
   - 不一致：`列名 / catalog.csvの値 / 第2ソースの値 / 第2ソースのURL` の形で列挙する。
   - どちらが正しいか分からない場合は判断せず、両方の値と出典を提示するだけにとどめる
     （断定しないという `CLAUDE.md` の方針）。

5. **報告する**
   - 対象の `sku_id` ごとに、不一致の有無と一覧を出す。
   - 不一致が無ければ「`verified=true` への変更を検討してよい」と伝える。実際に書き換えるかは
     ユーザーの判断に委ねる（このスキルはファイルを書き換えない）。
   - 不一致があれば、どちらの値を採用すべきかの判断はユーザーに委ね、`notes` 列に追記する文案だけ提案する。
