# coverage-eval

`data/coverage_sample.csv` に対する `resolve_listing` 相当の名寄せ結果（`npm run coverage`）を実行し、
「候補なし」だった出品を手がかりに、カタログへの追加候補を優先順位付きでリストアップするスキル。

`npm run eval`（正解データとの一致率）とは目的が違う点に注意：`coverage-eval` は
「そもそもカタログに無いものをどれだけ見落としているか」を見るためのもの。

## 手順

1. **カバレッジを実行する**
   ```bash
   npm run coverage
   ```

2. **出力を読む**
   - 「信頼度≥0.8の候補あり」「候補あり（信頼度<0.8）」「weak_matchesのみ」「候補なし」の内訳を確認する。
   - 「候補なしの出品を推定ラインごとに集計」のブロックに注目する：
     - `other-ip: <キーワード>` はキングダムハーツ以外の作品。カタログ追加の対象外（別IP展開の判断材料にはなる）。
     - 既存の `line_id` が推定として出ている行は「そのラインの別デザイン・別賞が抜けている」可能性が高い。
     - `unknown (no recognizable KH vocabulary)` はキングダムハーツ関連と思われるが、
       ラインもキャラも一致しない＝カタログに存在しないシリーズ・商品の可能性が高い。

3. **`scripts/weekly-report.mjs` の集計と突き合わせる（公開後・KVにデータがある場合）**
   ```bash
   npm run report:weekly
   ```
   - 「未解決トークン 上位20」「リクエストされた未対応IP」は、実際の利用ログから見た未カバー需要。
   - `coverage-eval` の推定ラインと重なる語があれば優先度を上げる。

4. **追加候補リストを作る**
   - 各候補について：推定ライン／該当出品タイトル（`data/coverage_sample.csv` の実例）／
     優先度（他IPからの流入が多い＝ニーズがある可能性、出現件数が多い、等）を短くまとめる。
   - 一次情報URLが分かるものは添える（分からなければ「要調査」と明記）。
   - `docs/SPEC.md` のカタログ列に沿って、次に `catalog-entry` スキルで下書きする対象の優先順を提示する。

5. **出力形式**
   - チャット上に箇条書きで「追加候補リスト（優先順）」として返す。ファイルへの書き込みは求められない限り行わない。
   - カタログを実際に追加する作業はこのスキルの範囲外。`catalog-entry` スキルに引き継ぐ。
