# outreach-reply

Kingdom Hearts のグッズについて英語圏コミュニティ（Reddit、Discord等）で聞かれた質問文を渡されたら、
このMCPサーバーのツールで調べた事実だけを根拠にした、売り込み色のない英語の返答を下書きするスキル。

## やってはいけないこと（厳守）
- **売り込み禁止**：「ぜひ使ってみて」「私が作ったツールです」のような宣伝文句、感嘆符の多用、
  「You should try my tool!」的な誘導は書かない。淡々と事実と根拠を答える。
- **断定しない**：真贋・相場は目安であり確定情報ではない（`CLAUDE.md`）。「This is 100% genuine」等は書かない。
- **出典なしの主張をしない**：ツールが返した `source_url` を必ず添える。ツールで確認できなかったことは
  「わからない」と正直に書く。
- **個人情報・出品者情報を晒さない**：質問文に含まれる出品者名・個人を特定できる情報は返答に含めない。

## 手順

1. **質問文を読み、必要なツールを呼ぶ**
   - 出品タイトル・商品名が含まれる → `resolve_listing`（可能なら価格・プラットフォームも渡す）
   - 特定SKUの詳細（寸法、再販歴等）を聞かれている → `explain_product`
   - 「アメリカから買うといくら？」等 → `estimate_landed_cost`
   - 見たことのない商品・シリーズを探している → `discover`
   - 複数質問がある場合は複数ツールを呼んでよい。

2. **ツール結果から返答を組み立てる**
   - 候補SKU（`candidates`）があれば、名前・`source_url`・`why`（一致理由）を使って
     「これはおそらく〜です、公式ページはこちら」と書く。
   - `candidates` が空で `weak_matches` のみ、または両方空の場合は、
     「confidently identify できない」旨と、次に確認すべき情報（`next_checks_en`）を伝える。
     不確かなのに断定しない。
   - `flags`（海賊版注意）があれば、断定せず「worth double-checking because ...」のトーンで伝える。
   - `price.note_en` / `acquisition.note_en` / `variety.note_en` があれば、
     「なぜこの価格・入手経路なのか」の説明として自然に組み込む
     （例：くじ景品なら「this was a kuji prize, so the ¥{msrp} is the per-draw price, not a per-item MSRP」）。

3. **計測用リンクを付ける**
   - Web版チェッカーのURLに `?src=` を付けて添える。`src` の値はチャネル名（例: `reddit`, `discord`）を使う。
     例：`https://<公開URL>/index.html?src=reddit`
   - 公開URLが分からない場合は `web/index.html` のコメントに書かれているMCPサーバーURLを参考に、
     ユーザーに実際のURLを確認してもらう（推測で存在しないURLを作らない）。

4. **返答の下書きを提示する**
   - 英語、簡潔、一次情報へのリンク付き。上から順に：識別結果 → 根拠（source_url） → 注意点（あれば）
     → 次の確認事項（あれば） → 計測用リンク（自然な形で、押し売りにならないように）。

5. **`docs/outreach_log.csv` に記録する（実際に投稿した後）**
   - 日付・チャネル・質問要約（原文そのままではなく要約）・返答要約・`src`・反応種別（投稿直後は `R0`、
     後で更新する）・フォロー質問（あれば）・24hクリック（あとで `?src=` の集計から埋める）を1行追記する。
   - `反応種別` の定義は `docs/demand_baseline.md` を参照。

## 出力形式
- チャット上に「返答案（英語）」として提示し、ユーザーが確認・編集してから実際に投稿できるようにする。
- 実際の投稿（Reddit/Discordへの送信）はこのスキルでは行わない。送信はユーザー自身が行う
  （送信は取り消せない行為のため）。
